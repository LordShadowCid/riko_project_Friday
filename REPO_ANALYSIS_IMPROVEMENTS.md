# Repo Analysis — Feature & Code Improvement Opportunities
Generated by deep analysis of 4 external repos against current Annabeth codebase.

---

## Repo 1: MekaHime Pipeline V1
`https://github.com/zeekk0/MekaHime-Pipeline-V1`
**What it is:** Retired first-gen AI-waifu voice pipeline: Whisper STT → Ollama LLM → Coqui TTS → **RVC voice conversion**

### What We Can Take
| Feature | Description | Priority |
|---------|-------------|----------|
| **RVC Voice Conversion** | After GPT-SoVITS generates TTS audio, run it through a trained RVC `.pth` model for hyper-realistic voice cloning. Eliminates the "TTS robot" quality issue. Uses `hubert_base.pt` + optional `rmvpe.pt` for pitch extraction. | 🔴 HIGH |
| **WebRTC VAD** | Real-time Voice Activity Detection using `webrtcvad` — more accurate than simple amplitude thresholding for deciding when the user has stopped speaking. Better than what we likely have now. | 🟡 MEDIUM |
| **External Whisper real-time** | Uses a dedicated real-time Whisper repo (not inline inference) — faster, non-blocking STT. | 🟡 MEDIUM |

**Key gap for us:** We have GPT-SoVITS but no RVC post-processing step. MekaHime's pipeline makes it clear RVC is the quality differentiator. Adding RVC on top of GPT-SoVITS would make Annabeth's voice dramatically more natural.

## Repo 2: MystiaTech/Mai
`https://github.com/MystiaTech/Mai`
**What it is:** Python AI companion with Ollama/LMStudio, SQLite persistent memory, self-improvement system, Discord bot, voice visualization, desktop avatar, Android sync.

### What We Can Take
| Feature | Description | Priority |
|---------|-------------|----------|
| **Self-Improvement System** | Annabeth analyzes her own server code, proposes Python patches, a second LLM pass does safety review (LOW/MEDIUM/HIGH/BLOCKED risk), non-breaking changes auto-apply, breaking changes prompt user. Full git audit trail. This is `src/selfmod/`. | 🔴 HIGH |
| **Model Auto-Switching** | Based on intent classification (already have `intent_classifier.py`!), auto-route to a smaller fast model for casual chat and a larger model for stories/code/detailed tasks. Mai has this in `src/models/`. | 🔴 HIGH |
| **Memory Auto-Compression** | When SQLite memory grows past a token threshold (Mai uses 100k), run a summarization pass that collapses old entries into condensed "memory chunks". Prevents RAG recall from degrading over time. | 🔴 HIGH |
| **Long-Term Personality Layers** | Distill recurring patterns from conversation history into persistent personality modifiers stored separately from raw chat logs. "Annabeth has learned that user prefers X" — persists across resets. | 🟡 MEDIUM |
| **Import/Export System** | Export full memory + personality state as a portable file, import on a new machine. `src/import_export/`. Useful for users. | 🟡 MEDIUM |
| **Audit Trail** | Log every AI decision, code change, and tool call with timestamp + reasoning to a structured audit DB. | 🟡 MEDIUM |
| **GPU/Resource Monitoring** | Use `pynvml` to monitor GPU VRAM/utilization. Report it to users on request ("How loaded are you?"). Already have hardware profiling logic this would extend. | 🟢 LOW |
| **Offline Message Queueing** | Queue WebSocket messages locally when the server is down; replay when reconnected. Makes the system more resilient. | 🟢 LOW |
| **Voice Visualization** | Real-time waveform/frequency spectrum display in the web UI during voice input. Could render in `companion.html`. | 🟢 LOW |

**Key insight:** Mai's self-improvement + model switching are the two highest-value features. Model switching is especially easy since we already have `intent_classifier.py` — we just need to pass different Ollama model names based on intent category.

## Repo 3: XargonWan/Synthetic_Heart
`https://github.com/XargonWan/Synthetic_Heart`
**What it is:** Modular Python framework for persistent AI persona with database-backed memory, multi-platform interfaces (Discord/Telegram/Matrix/WebUI), VRM avatar system, plugin architecture.
**Already adopted from this repo:** `emotion_state.py`, `reflection_loop.py`, `bio_manager.py`

### What We Have NOT Yet Taken
| Feature | Description | Priority |
|---------|-------------|----------|
| **G.R.I.L.L.O. Full Plugin** (`plugins/grillo_plugin.py`) | Our `reflection_loop.py` is a simpler version. The full Grillo system has: memory consolidation beats, tag elaboration, self-reflection prompts, **curiosity beats** (Annabeth proactively gets curious about topics), **relationship health checks**, diary scheduling, and the ability to enqueue actions for other plugins. Much richer than what we have. | 🔴 HIGH |
| **Recon System** (`core/recon.py` + `plugins/recon_*.py`) | Before generating a response, runs a "reconnaissance" pass: evaluates what language to respond in, what tone to use, what memories are relevant. Pre-populates the LLM context with the right memories + tone before the main call. We do basic context injection but not a dedicated pre-pass. | 🔴 HIGH |
| **Memory Search** (`plugins/memory_search.py`) | Semantic/keyword search through diary and memory entries. Instead of injecting all recent memories, searches for specifically relevant ones. We currently inject recent memories in a sliding window — semantic retrieval would be far more efficient for long-term users. | 🔴 HIGH |
| **Synth Tagging** (`core/synth_tagging.py`) | Auto-tags every message/memory entry with topics, entities, sentiment, etc. Makes memory search much more effective. Tags like "weather", "work", "user_preference", "emotional_state" are auto-applied by an LLM pass. | 🟡 MEDIUM |
| **Debrief System** (`core/debrief.py` + `plugins/debrief_action_intent.py`) | After each conversation exchange, runs a debrief pass: consolidates what was learned, what actions to take, what to remember. Currently our reflection only runs on a timer — debrief runs post-response. | 🟡 MEDIUM |
| **Chat Attention Triggers** (`core/chat_attention.py`) | Define keyword/pattern triggers that route to special handlers (e.g., if user says "remember this" → force diary entry; "what did we talk about" → trigger memory retrieval). | 🟡 MEDIUM |
| **Variables Engine** (`core/variables_engine.py`) | Template variables in prompts (`{{user_name}}`, `{{current_time}}`, `{{weather}}`, `{{relationship_days}}`) that get auto-substituted before LLM calls. Makes prompt engineering much cleaner and consistent. | 🟡 MEDIUM |
| **Karada Animation API** (`core/karada_api.py`, `karada_transport.py`, `karada_ws_transport.py`) | A dedicated WebSocket-based animation control API separate from the main avatar WebSocket. Sends structured animation state changes (idle → talking → thinking → laughing) with proper state machine semantics. Better than sending raw animation names. | 🟡 MEDIUM |
| **Facial Expression Plugin** (`plugins/facial_expression_plugin.py`) | Derives facial expressions from emotion tags in LLM output — if Annabeth says something with `[emotion:surprised]`, the plugin fires the right blendshape. Integrated with audio duration so expressions hold for the right time. | 🟡 MEDIUM |
| **Ollama Compatibility Layer** (`interface/ollama_compat_server.py`) | Exposes Annabeth's LLM as a standard Ollama endpoint — so tools like Open WebUI, Continue.dev, etc. can connect directly to Annabeth. Mirrors `/api/generate`, `/api/chat`, `/api/tags`. | 🟢 LOW |
| **Weather Plugin** (`plugins/weather_plugin.py`) | Real-time weather awareness. Annabeth can reference "it's rainy in your city today" in conversation. Has a WebUI endpoint too. | 🟢 LOW |
| **Presence Manager** (`core/presence_manager.py`) | Tracks what interface/activity Annabeth is currently engaged in and reflects it in the avatar state (busy typing, idle, thinking). Even across multiple simultaneous connections. | 🟢 LOW |
| **TTS Lip Sync** (`plugins/tts_lipsync.py`) | Derives per-phoneme lip sync timing from TTS audio duration. Drives VRM blendshapes precisely instead of a generic "talking" animation. | 🟢 LOW |
| **Action Security Schema** (`core/action_schema_converter.py`, `action_safety.py`) | Each plugin action has a declared security level. Prevents a plugin from doing something destructive without user confirmation. Useful as we add more tool-use. | 🟢 LOW |

## Repo 4: shinyflvre/Mate-Engine (v3.3 / 3.4 prep)
`https://github.com/shinyflvre/Mate-Engine`
**What it is:** Desktop VRM companion app (Unity C#). We've already adopted the core architecture. Currently prepping v3.4.
**Already adopted:** SettingsManager, RadialMenu, SleepController, IKController, WalkAnimationController, DragAnimationController, DragPoseController, OccluderQuadManager, WindowSnapper, DesktopAmbientProbe, AccessoryManager, AnimationBlendController, VrmModelLibrary, VrmFilePicker, FPSController, MemoryOptimizer.

### What We Have NOT Yet Taken
| Feature | Description | Priority |
|---------|-------------|----------|
| **Event-Based Contextual Messages** | Generates a contextual message when user drags avatar, starts dance mode, avatar sits on a window, or sits on taskbar. E.g., "Whee!" when dragged, "I love this song!" when dancing. Currently our messages are timer-based; event-based makes it feel reactive. | 🔴 HIGH |
| **Touch Regions** | Different parts of the avatar body trigger different reactions when clicked/touched (head pat → happy, poke face → surprised, etc.). Currently we have a basic touch response but not region-specific. | 🔴 HIGH |
| **Screensaver Mode** | After N minutes of user idle (not just app idle), Annabeth transitions to a gentle ambient screensaver animation. Auto-wakes on mouse movement. | 🟡 MEDIUM |
| **Discord Rich Presence** | Shows "Chatting with Annabeth" / "Annabeth is dancing" in the user's Discord status. Uses the Discord Game SDK overlay. Adds social visibility. | 🟡 MEDIUM |
| **Chibi Mode** | A toggle that scales the avatar down to a small "chibi" size. The `SettingsData` already has an `enableChibi` bool we can wire up (check if already present). | 🟡 MEDIUM |
| **Expression Based on Movement** | Avatar's facial expression reacts to physics state — when dragged fast → surprised/scared expression, when dropped → relieved expression, when walking → determined expression. Currently movement and expressions are decoupled. | 🟡 MEDIUM |
| **Avatar SFX** | Sound effects tied to specific avatar events (drag start, drop, dance start, touch). Not TTS voice — these are short reaction sounds (giggles, gasps, etc.) on the Unity side. | 🟡 MEDIUM |
| **Post-Processing Bloom + AO** | Visual quality upgrades — Bloom (glowing lights on avatar) and Ambient Occlusion. Mate-Engine 3.x has both. Already have AmbientProbe; these are the renderer-level effects. | 🟢 LOW |
| **Big Screen Mode** | A full-screen billboard mode where the avatar fills the whole screen instead of a corner overlay. Useful for streams. | 🟢 LOW |
| **Debugging Menu** | An in-app debug overlay toggled by a key combo that shows: current animation state, IK weights, emotion state, memory queue depth, WebSocket connection status. | 🟢 LOW |
| **Blendshape Edit Support** | In-app UI to manually adjust VRM blendshapes (not just the preset expressions). Lets users fine-tune Annabeth's resting face. | 🟢 LOW |
| **Custom Dance Player** (community mod concept) | A UI for adding/importing custom `.vrma` dance files at runtime without rebuilding the project. We have `animations/` folder — expose this in settings. | 🟢 LOW |
